# 飞牛影视统一入库维护系统

这是一个面向家庭 NAS 的影视资源搜索、审核和自动入库工具。

访客可以搜索并提交想看的影视，管理员负责审核和查看任务进度。系统可以把资源转存到网盘，
再通过 OpenList 整理目录、刷新 STRM，最后交给飞牛影视等媒体库识别。

项目为自用项目，开源给同需求用户

项目主要是给网盘使用，适合移动云盘空间大的用户（我大概有上百T)，目前流程是，移动云盘资源直接进入openlist,6盘离线到6盘空间，夸克资源多，空间小，API容易风控，不能302等一系列问题，所以目前只是找资源然后高速下载转存到移动云盘，简单来说，目前项目是主要为移动云盘服务，但是，可以支持下载资源到夸克和本地（此功能还需再次优化）。

## 1. 项目介绍

### 能做什么

- 提供访客搜索和提交页面。
- 提供管理员审核、任务重试、日志和运行状态页面。
- 支持 PanSou 聚合搜索（可选内置，一行开关启用），也可以启用 BTBTLA 作为补充磁链来源。
- 支持夸克、139 移动云和 6盘等入库线路。
- 支持访客按文件或文件夹选择需要入库的内容。
- 支持 OpenList 目录整理，可按 TMDB 信息生成标准影视名称。
- 识别不准确时可以人工修改，也可以跳过改名，直接放入正确的分类目录。
- 支持电影、电视剧、动漫、综艺和其他分类。
- 支持邮件、Webhook 和每日摘要通知。
- 支持定时追更和每日热榜候选。

### 使用流程

```text
访客搜索影视
  → 选择资源并提交
  → 管理员审核
  → 网盘转存或离线下载
  → 移入任务暂存目录
  → OpenList 整理或人工跳过整理
  → 刷新 STRM
  → 媒体库更新
```

PanSou 聚合搜索可作为可选内置服务随编排启动（默认关闭，在 `.env` 加 `COMPOSE_PROFILES=pansou`
启用）；也可以在后台填写自建的外部 PanSou 地址。项目不会自动提供
OpenList、第三方网盘账号或 TMDB Token。它负责把这些已有服务连接起来，并统一管理整个入库过程。

### 页面入口

| 页面 | 地址 |
|---|---|
| 访客页面 | `http://服务器IP:5251/` |
| 管理后台 | `http://服务器IP:5251/admin/login` |
| 健康检查 | `http://服务器IP:5251/health` |
| API 文档 | `http://服务器IP:5251/swagger` |

## 2. 准备工作

### Docker 环境

建议使用：

- Docker Engine 20.10 或更高版本。
- Docker Compose v2。
- Linux 容器模式。
- `amd64` 或 `arm64` 设备。

### 外部服务

根据实际使用的功能准备，不需要全部安装：

| 服务 | 是否必需 | 用途 |
|---|---|---|
| PanSou | 可选 | 聚合搜索源。可在 `.env` 加 `COMPOSE_PROFILES=pansou` 启用内置容器（fish2018/pansou），也可以在后台改填自建外部 PanSou 地址 |
| 内置夸克 Provider | 使用夸克线路时需要，在后台使用夸克 APP 扫码登录（自动提取并加密保存 Cookie） | 通过夸克官方网页 API 检查分享并原生转存 |
| 内置天翼 Provider | 使用天翼线路时需要，在后台使用账号密码登录；风控时输入图片验证码 | 自动维护 Token，通过天翼网页 API 获取分享目录、原生转存并轮询校验 |
| OpenList | 使用目录整理或 STRM 时需要 | 统一访问网盘、整理真实目录、生成 STRM |
| 139 移动云认证 | 使用移动云线路时需要 | 官方直转或上传文件 |
| 6盘账号 | 使用磁链离线下载时需要 | 解析磁链并创建离线任务 |
| TMDB Token | 建议配置 | 帮助识别影视名称、年份和季集 |
| AI 接口 | 可选 | 仅用于低置信识别建议 |
| 飞牛媒体库接口 | 可选 | 整理完成后触发媒体库刷新 |

天翼账号默认通过后台的“账号密码登录”接入。系统按天翼登录协议对账号密码做 RSA 加密；若天翼触发风控，会在登录弹窗中显示图片验证码并等待输入。登录成功后 `accessToken`、`refreshToken` 和过期时间会加密保存，运行时优先使用 Access Token，失效后自动刷新并写入新的账号修订。Refresh Token 不可用时再回退到已保存的 SSON 或账号密码；后台无人值守重登若再次触发验证码，会要求管理员重新登录。SSON 仍可作为恢复凭证，支持只填 Cookie 值或填写 `SSON=...`。私密分享访问码随资源提交，不写入账号凭证。

夸克运行时只使用后台“网盘入库 → 云盘账号”中激活的 Provider 账号。系统不再读取全局
`quark` Cookie、高级配置 Token 或环境变量回退；账号无法解密、登录态过期或凭证为空时会明确
提示当前账号不可用，需要在账号工作区重新登录或切换账号。

### 磁盘空间

数据库、后台配置和自动生成的进程认证令牌默认保存在 `data`，日志默认保存在 `logs`。
浏览器会话签名密钥由 `FNOS_ROOT_KEY` 按 `app-session` 用途派生，不单独配置或持久化。
`rclone/temp` 可能临时保存完整视频文件，如果系统盘空间有限，应在 `.env` 中把
`RCLONE_TEMP_HOST_PATH` 改到容量较大的存储盘。

## 3. 如何部署

### 方法一：命令行部署

下载项目并启动：

```bash
git clone https://github.com/aichuguang/fnos-search.git
cd fnos-search
cp .env.example .env
openssl rand -hex 32
# 把上一行生成的 64 位 hex 填入 .env 的 FNOS_ROOT_KEY
docker compose up -d
```

第一次启动会自动完成以下工作：

- 拉取 `aichuguang/fnos-search:latest`。
- 启动 Web 容器和独立的 rclone Worker 容器；启用了 `COMPOSE_PROFILES=pansou` 时还会启动内置 PanSou 聚合搜索容器。
- 创建数据库和全部表结构。
- 创建默认持久化目录。
- 校验你提供的 `FNOS_ROOT_KEY`，派生应用会话签名密钥，并生成 Worker 控制令牌。

查看运行状态：

```bash
docker compose ps
docker compose logs -f fnos-media-import
```

### 方法二：NAS Docker 面板部署

1. 打开 NAS 的 Docker 管理页面。
2. 新建 Compose 或“项目”。
3. 上传项目目录，或把 `docker-compose.yml` 和需要的宿主机目录放在同一个项目目录。
4. 根据 `.env.example` 创建 `.env`（或在面板中添加环境变量），至少填写一条 64 位 hex 的
   `FNOS_ROOT_KEY`；需要自定义存储位置时，建议同时填写绝对路径。
5. 启动项目。
6. 浏览器打开 `http://NAS-IP:5251/admin/login`。

默认登录信息：

```text
用户名：admin
密码：admin
```

登录后页面会持续提示修改默认密码。

### “等待人工确认”如何处理

“待审核”是尚未创建入库任务的内容审批，可以点击“批准”。“等待人工确认”通常表示已经关联的
入库任务暂停，不是重新批准一次：在访客请求列表点击“处理确认”，直接进入原任务。

- 有可恢复回执时，处理提示的问题后选择“确认并继续”，按原任务记录续跑。
- 提示提交记录存在但回执缺失时，先核对详情展示的冻结来源暂存、目标目录和网盘任务列表。
  **只有确认没有本次文件、没有进行中或可能稍后完成的外部操作，才选择“确认未执行，重新提交”**。
  必须填写实际核对说明并再次确认；误判可能产生重复文件或任务，程序不能替代人工证明外部操作未发生。
  原任务编号、原提交记录及管理员核对说明保留审计，不删除数据库或直接标记入库成功。
- 若已有文件、已存在网盘任务或无法确定结果，不要使用“未执行”确认，也不要新建重复任务；保留原任务与执行证据。
- 页面过期、原 Worker 租约仍有效、已有回执或任务已取消时会拒绝重新提交。提示“人工确认已保存，但入队未确认”
  时不要再次确认，刷新状态并检查 Worker 队列。

“传输中心”以当前影视名称和进度为主，默认只显示当前任务；已完成/取消任务只在底部保留一个
默认收起的“已结束记录”入口，展开最多展示 5 条简要记录，不占用顶部统计或主任务区域。
失败和人工复核任务保留在“需处理”。已结束的下载/上传步骤与服务状态同样默认折叠；
单文件 100% 不等于整个任务入库完成。底部历史仅包含 Worker 最近观测，完整历史请到“正式任务”查看。
有界中继期间，同一任务卡可同时显示当前上传文件与下一下载文件，两条进度、速度和反馈时间独立计算；
预下载缓存满只显示等待释放，不会冒充上传失败或整任务完成。

“日志中心”仅显示简要服务状态和诊断记录；“查看入库任务”会跳转到任务列表。当前版本不支持旧的全局目录扫描，
搬运由 Worker 按具体 V1 入库任务自动调度，不需要另点“启动搬运”。旧客户端调用全局启动接口会收到
`409 / RCLONE_JOB_REQUIRED`，不能通过补任意路径参数绕过任务校验。

分享读取接口确认资源失效时，夸克、移动云、天翼统一提示“分享资源已失效或被删除，请更换有效链接后重试”。
六盘离线资源按明确的失效业务码/原因提示；普通接口 404、账号登录、提取码、限流与网络故障不会误报资源失效。
底层状态码和脱敏诊断仍保留用于排障，失效资源不会继续盲目提交或重试。

移动云已有完整逐文件成功回执、但最后上传完成状态未保存时，原任务恢复会先只读核对原目标目录中的
文件 ID、名称、大小与归属，证据齐全后补齐上传回执，再继续正常校验与入库；不会重新上传。
只有网盘里“看到了文件”或只有底层上传 sidecar 而缺少原任务成功回执时，仍需人工核实，不能确认“未执行”。

### 夸克只保存勾选的文件

选择文件夹内部条目时，会保留所选文件 ID、相对路径和所属目录，不再因为“当前预览条目全部勾选”
就自动改为保存整个父文件夹。只有显式选择父文件夹时才保存整个目录；预览可能有截断，不能据此推断目录已全选。

提交成功表示请求已入队，实际执行时会重新读取夸克列表与转存令牌。子目录成功响应按夸克 `code=0` 协议处理，
不要求额外存在 `success=true`。若真实选择已失效、文件 ID 不匹配或令牌缺失，会明确报错并停止本次提交，
不忽略缺项、不降级成整个分享，也不把确定的选择错误当作网络故障反复重试。

升级不会改写已冻结任务的选择。如果旧任务创建时子项已经被折叠成整个父目录，原始子项信息无法凭空恢复；
需要在新版中按实际需要重新勾选提交，而不是直接重试旧的整目录快照。

### 配置 rclone

只有启用跨 Provider 来源落地、受控本地下载或通用 OpenList 目标时，才需要完成这一步。
移动云和天翼作为目标时，rclone 只把来源下载到本地 relay，最终写入分别由移动云 API 和
189CloudPC API 完成，不通过 rclone/WebDAV 上传文件字节。

登录管理后台，进入“系统设置 → 飞牛与 rclone”，填写以下内容：

- Remote 名称：默认 `MP`
- OpenList WebDAV URL：例如 `http://host.docker.internal:5244/dav`
- OpenList 用户名和密码

点击“保存并检测”。连接成功后即可使用，不需要进入容器，也不需要手工处理密码。

只有页面无法使用时，才需要手工编辑 `rclone/config/rclone.conf`：

```ini
[MP]
type = webdav
url = http://你的OpenList地址:5244/dav
vendor = other
user = OpenList用户名
pass = rclone处理后的密码
```

`MP` 是默认 remote 名称，不要随意修改。手工配置时，密码可以这样处理：

```bash
docker exec fnos-rclone-worker rclone obscure '你的OpenList密码'
```

把输出内容填到 `pass`。然后检查是否连接成功：

```bash
docker exec fnos-rclone-worker rclone listremotes --config /config/rclone/rclone.conf
docker exec fnos-rclone-worker rclone lsd "MP:" --config /config/rclone/rclone.conf
```

如果日志出现 `didn't find section in config file ("MP")`，说明 Worker 当前挂载的
`rclone.conf` 没有 `[MP]`，需要在“飞牛与 rclone”中重新保存并检测，或确认
`RCLONE_CONFIG_HOST_PATH` 指向了实际配置目录。若随后出现
`/data/relay/job-<id>: Permission denied`，则是 `FNOS_RELAY_HOST_PATH` 对应的宿主机目录
不可由容器用户 `10001:10001` 写入；请先创建目录并授予该 UID/GID 写权限，再重新编排：

```bash
mkdir -p /你的目录/fnos-search/relay
chown 10001:10001 /你的目录/fnos-search/relay
chmod 770 /你的目录/fnos-search/relay
docker compose up -d --force-recreate
```

新版本入口脚本会在 Worker 启动时自动修复 `/data/relay` 根目录权限；宿主机文件系统不允许
容器内 `chown` 时，仍需按上面的方式预先设置权限。

若日志出现 `已有 rclone 搬运任务运行中，本次未启动，稍后由队列重新调度`，说明 Worker 内另一个
rclone 搬运进程仍持有互斥锁。本次运行会以退出码 75 结束并自动回滚到队列，按退避间隔重排，
不会被记成成功，也不会触发上传；连续多次拿不到锁才会转为失败并交给传输重试。互斥锁基于
`flock`，持锁进程退出后立即释放，无需手工清理锁文件。若长期占锁，请检查是否有残留的
rclone 进程：

```bash
docker exec fnos-rclone-worker ps aux | grep -E "rclone|fnos_rclone_worker"
```

如果日志仍是旧提示 `已有 rclone 搬运任务运行中，本次跳过`，接着却出现“立即唤醒传输执行”及
“中继目录为空或不存在”，含义是：下载根本没有开始，旧脚本却以成功退出，程序随后误去空目录上传。
这不是移动云目标目录错误，也不要靠反复建空目录或删除数据库记录处理。请同时更新 Web 和 Worker
镜像；新版本也会识别旧脚本的这条提示，把退出码 0 纠正为未启动，而非把它算作下载成功。
更新后重试原任务即可让已成功但没有中继文件的旧 run 失效并重新下载；不要新建重复任务或强制放行上传。

更详细的说明见 [rclone 配置](rclone/README.md)。

### 小容量中继盘：同任务有界预下载

移动云、天翼的跨网盘中继采用 **1 个下载 + 1 个上传**：上传第 N 集时可下载同一任务的第 N+1 集，
默认额外预下载 1 集（包含下载中的文件，最多当前文件加下一集）；可配置为 2 集，最多保留 3 集。
不跨入库任务预取、不增加上传并发、不改变原文件幂等键；上传慢且缓存窗口已满时，下载正常等待。

| 环境变量 | 默认值 | 作用 |
| --- | ---: | --- |
| `RELAY_PREFETCH_FILES` | `1` | 额外预下载文件数，支持 `0`/`1`/`2`；`0` 为单文件串行，但仍检查新磁盘预算。 |
| `RELAY_CACHE_MAX_BYTES` | `21474836480` | 中继缓存预算，默认 20 GiB，包含当前上传、就绪文件及在途下载完整预留。 |
| `RELAY_DISK_RESERVE_BYTES` | `1073741824` | 实际磁盘安全余量，默认 1 GiB；按实际 NAS 容量调整。 |

- 从第一集开始、下载前就检查文件大小、数量、预算和磁盘余量；多个任务共享缓存保护，旧缓存及未知部分文件不被忽略或自动删除。
- 新版受控本地下载使用 `--inplace`，按已落盘字节抵扣预留；运行中每秒检查余量，空间不足安全停止当前下载并保留文件。
  这不是操作系统磁盘配额，不能保证其它程序突然大量写入时磁盘绝不耗尽。
- 正常缓存等待立即释放下载执行槽并交回队列，不消耗失败重试预算，也不再受旧版 10800 秒缓存等待限制。
- 只有远端验证和成功回执持久化都完成，才释放媒体缓存。上传失败、未知结果或取消会停止补位；
  已在途的预下载受固定预算及运行期检查约束，暂停后原回执/部分文件保留，不通过删除文件或重复上传绕过问题。
- 每个文件有独立上传幂等键；崩溃恢复复用回执，不重复上传已完成文件。小型隐藏回执保留到整个任务最终校验、ACK 后清理。
- 源网盘落地区仍保留到整任务确认，避免下载完成就误删来源。旧批量任务中已完整落地的缓存可按文件逐个处理；
  旧上传结果不确定时进入人工复核，不通过新幂等键强制重传。
- 单个文件仍必须能放进中继盘；例如只剩 3.13 GB 时无法中继约 5.2 GiB 的视频。
  历史残留、其它程序及并发任务占用的空间也计入检查，系统不会自动清空整个缓存目录。

发布时 Web 与 Worker 必须同时更新到同一版本，保留现有数据库和 `FNOS_RELAY_HOST_PATH` 挂载；
无需数据库 Schema 迁移。同步更新编排和三项可选环境变量后重新创建容器，单纯 restart 不会加载新的 `.env`。
预下载数量及安全余量在任务首次启用时冻结，不会因改环境突然扩大已有窗口；提高缓存字节上限可在保留原任务的情况下生效，
用于恢复单文件超过原预算的等待。降低预算、调整数量/余量仅用于新启用的任务。
升级前先停调度并等待当前上传结束，避免新旧数据面混跑；旧 v1 清单通过显式检查升级为 v2。
回滚优先在当前版本设置 `RELAY_PREFETCH_FILES=0`（作用于新启用任务），保留 v2 清单的兼容读取。
**已有 v2 清单不能交给只认识 v1 或旧版整批中继的代码重跑**；不要删除缓存清单、上传回执或重建入库任务。

### 入库完成、人工确认与取消边界

- Organizer 人工确认只是完成整理，不等于入库成功；关联的传输任务还需完成最终文件校验、ACK 及任务级清理。
- 网盘提交已有持久栅栏、但操作回执缺失时，取消不会自动删除来源、缓存或部分目标；应先核对外部任务，不能用取消绕过未知提交的保护。
- 同资源的多个公开请求可复用一个正式任务，但创建补偿只能撤销持久所有权匹配且全局尚未被任何请求绑定的任务。
  已绑定共享任务不会因另一请求取消而被撤销，已取消的正式任务也不会被新的请求绑定。
- 创建失败会明确反馈到请求状态；移动云、天翼的显式无效选择会被拒绝，不会悄悄改成转存整个分享。

### 配置管理后台

进入“系统设置”后，建议按以下顺序配置：

1. 在“个人设置”修改管理员密码。
2. 搜索：默认不内置。想用内置 PanSou 时在 `.env` 加 `COMPOSE_PROFILES=pansou` 后重新编排；
   使用自建外部 PanSou 时，在“搜索与线路”填写地址。
3. 在“网盘入库 → 云盘账号”登录夸克、天翼、移动云或 6盘账号。
4. 在“网盘入库 → OpenList”创建连接并检测挂载。
5. 在“网盘入库 → 保存位置 / 入库规则”选择目标并生成分类目录。
6. 在“OpenList/TMDB/AI”中仅调整通用运行参数、TMDB 和 AI；OpenList 身份凭证不在高级配置中保存。
7. 需要自动整理时再开启 Organizer，需要通知时配置 SMTP 或 Webhook。

高级配置的保存与导入统一使用 `fnos-media-import/advanced-config`、`version: 1` 的版本化文档。
后台导出的 JSON 可以重新导入；裸 `config` 对象、旧版全局网盘凭证和旧分类路径字段会被直接拒绝，
不会自动迁移或静默回退。

“全量配置备份”是另一种文档：`fnos-media-import/full-backup`，现使用 `version: 2`，包含账号选择、
OpenList 连接和挂载的完整不可变修订。旧 v1 全量备份缺失这些关键历史，不能安全恢复，导入时会拒绝；
请升级原系统后重新导出 v2，不能只修改 JSON 的版本号或补空数组。管理员凭据仍不随备份导出。
导入前应进入维护窗口、停止提交新任务并保留完整 SQLite 备份；已被旧版导入删除的历史无法从旧 JSON
重建，需要从原完整数据库备份恢复。高级配置文档仍为 v1，与全量备份 v2 不冲突。

全量配置导入会在写事务内复查排队、执行、待恢复任务以及尚未完成的网盘登录授权；存在时返回
`409 CONFIG_RESTORE_BUSY`，不会覆盖配置。请先完成或取消登录授权，并等待任务安全结束。
已过期且仍为 `waiting` 的登录会话会先按正常登录接口的规则结束，不会因废弃的登录窗口永久阻塞导入；
正在轮询或保存登录结果的会话不会仅因到期时间被清除，仍需完成或取消后再导入。
如果导入提交后运行时重载失败、同时又有新任务或授权开始，系统不会强行回滚它们正在使用的配置，
会报告回滚未完成；此时先停止新提交、处理在途任务，再核对配置并重载/恢复，不要反复强行导入。

配置完成后，建议先提交一个小资源测试完整流程，再开始批量使用。

访客提交失败且尚未创建正式入库任务时，管理员可在请求列表或详情点击“重试提交”，沿用原请求编号重新入队。
已关联正式任务的请求应进入任务详情处理；已完成、已取消或仍在执行的 Worker 不会被该入口重新激活。
API 调用方使用原批准接口并显式传 `retry: true`，普通批准不隐式重启失败任务。

#### 多网盘账号与规则的安全行为

一套部署可接入多个网盘和保存位置；来源使用该 Provider 的当前账号，保存位置独立绑定目标账号。
“重新登录”只用于恢复同一个真实账号，不用于把账号 A 替换成账号 B。检测到不同的 Provider 稳定身份时，
会拒绝覆盖并要求新增独立账号；凭据变化而无法证明身份相同也会拒绝，原账号、选择及映射保持不变。
旧账号尚无稳定身份记录时，会尝试只读验证旧凭据；旧凭据已失效、Provider 又不能提供可信身份时，需新增账号，
不能用昵称或手填用户名跳过验证。正常的、绑定原凭据修订的自动 Token 刷新不受此限制。

重新登录已有账号不会抢占管理员已经选择的其它默认账号；若希望切换来源，请显式点击“设为当前”。
中继认证失败只停止该账号的对应凭据修订，新的已验证修订可以继续尝试，不再要求重启 Worker 解除旧拦截。
这不会改写旧任务的冻结账号，也不会自动重传上传结果未知的文件。

仅设置“电影”的规则会保留其它分类未分配，不会在刷新后自动扩大到全部分类。
保存规则时创建、更新和删除均校验完整快照；出现冲突会保留当前表单选择，请刷新并核对后再保存，不要盲目重试。

自定义 API 客户端需先从 `GET /api/admin/storage-setup`、`GET /api/admin/source-assignments` 或
`GET /api/admin/routing-matrix` 取得 `routing_token`，再在对应的规则 PUT 请求中原样传回。
`PUT /api/admin/storage-setup/routes` 和 `PUT /api/admin/source-assignments` 缺 token 返回
`428 / ASSIGNMENT_SNAPSHOT_REQUIRED`，旧 token 返回 `409 / ASSIGNMENT_CONFLICT`；保存后重新 GET 获取新快照。
分类 `assignment_revisions` 的 `null` 表示“读取时尚不存在”，不是忽略版本检查。Swagger 已同步此契约。

### 编排目录设置

`docker-compose.yml` 不需要手工修改。默认会在编排文件所在目录创建 `config`、`data`、`logs`
和 `rclone` 子目录。

飞牛、群晖等 Docker 面板可以直接在 Compose 项目或编排的“环境变量”区域添加下表变量，
不需要创建 `.env` 文件。命令行部署需要自定义时，才复制环境变量模板：

```bash
cp .env.example .env
```

#### 正式部署变量

以下是 `docker-compose.yml` 支持的全部用户配置变量。新部署只需生成一把根密钥。

| 变量 | 默认值 | 是否建议配置 | 说明 |
| --- | --- | --- | --- |
| `APP_VERSION` | `latest` | 正式环境建议 | 应用镜像标签。固定为具体版本可避免重新编排时意外升级。 |
| `APP_PORT` | `5251` | 按需 | Web 页面映射到宿主机的端口。只填写端口数字，例如 `5251`。 |
| `TZ` | `Asia/Shanghai` | 按需 | 应用和 rclone 容器使用的时区。 |
| `APP_CONFIG_HOST_PATH` | `./config` | 按需 | 可选 `config.yaml` 所在的宿主机目录。 |
| `APP_DATA_HOST_PATH` | `./data` | 强烈建议确认 | SQLite 数据库、后台设置、数据库备份和 Worker 控制令牌的持久化目录。必须是当前 NAS 的本地文件系统，重新编排必须继续使用原目录。 |
| `APP_LOGS_HOST_PATH` | `./logs` | 按需 | 应用运行日志目录，分别保存 `web.log` 和 `worker.log`。 |
| `RCLONE_CONFIG_HOST_PATH` | `./rclone/config` | 强烈建议确认 | `rclone.conf` 持久化目录，保存 OpenList WebDAV Remote 配置。 |
| `RCLONE_CACHE_HOST_PATH` | `./rclone/cache` | 按需 | rclone 缓存目录，可清理，但运行中不要删除。 |
| `RCLONE_TEMP_HOST_PATH` | `./rclone/temp` | 建议配置 | 搬运完整媒体文件的临时目录，应放在空间充足的磁盘。 |
| `FNOS_RELAY_HOST_PATH` | `./rclone/relay` | 建议配置 | 跨 Provider 写入移动云或天翼时的共享中继目录，Web 与 Worker 都挂载到 `/data/relay`。rclone 只负责下载，随后由目标 Provider 原生 API uploader 上传；应放在空间充足的磁盘。 |
| `RCLONE_LOCAL_STORAGE_HOST_PATH` | `./rclone/local-storage` | 按需 | 本地存储目标的宿主机挂载目录，挂载到 Worker 的 `/storage-targets`。仅当使用本地文件夹目标时配置，必须指向预先挂载的独立目录，不能复用 `APP_DATA_HOST_PATH`。 |
| `FNOS_ROOT_KEY` | 无 | 必填 | 唯一的 32 字节根密钥，填写 64 位 hex。程序通过 HKDF-SHA256 为 Flask 会话、账号、OpenList、授权会话、来源快照和通知派生隔离子密钥。可用 `openssl rand -hex 32` 生成。 |
| `RCLONE_WORKER_CONTROL_TOKEN` | 空，自动生成 | 新部署不要填写 | Web 与独立 rclone Worker 之间的内部 Bearer Token。留空时生成并保存到 `APP_DATA_HOST_PATH/.secrets/rclone_worker_control_token`，重新编排会继续使用原值。 |
| `COMPOSE_PROFILES` | 空 | 按需 | 启用可选服务。填写 `pansou` 时编排会额外启动内置 PanSou 聚合搜索容器；留空则只有 Web 和 Worker 两个容器。 |
| `PANSOU_USERNAME` | `fnos-search` | 按需 | 内置 PanSou 聚合搜索的登录账号。该服务仅容器内网可达，不对宿主机开放端口。 |
| `PANSOU_PASSWORD` | `fnos-search` | 按需 | 内置 PanSou 聚合搜索的登录密码。修改后需要重新编排才能生效。 |
| `PANSOU_IMAGE` | `ghcr.io/fish2018/pansou:latest` | 正式环境建议 | 内置 PanSou 镜像。固定为具体版本可避免重新编排时意外升级。 |
| `PANSOU_CACHE_HOST_PATH` | `./pansou/cache` | 按需 | 内置 PanSou 搜索缓存目录，可清理。 |

NAS 面板示例：

```env
APP_VERSION=latest
APP_PORT=5251
TZ=Asia/Shanghai

APP_CONFIG_HOST_PATH=/你的目录/fnos-search/config
APP_DATA_HOST_PATH=/你的目录/fnos-search/data
APP_LOGS_HOST_PATH=/你的目录/fnos-search/logs
RCLONE_CONFIG_HOST_PATH=/你的目录/fnos-search/rclone/config
RCLONE_CACHE_HOST_PATH=/你的目录/fnos-search/rclone/cache
RCLONE_TEMP_HOST_PATH=/你的大容量目录/fnos-search/temp
FNOS_RELAY_HOST_PATH=/你的大容量目录/fnos-search/relay
FNOS_ROOT_KEY=请填写64位hex根密钥
```

面板中只添加需要覆盖的变量即可，不必逐项填写。相对路径以 Compose 项目目录为基准；NAS
面板的项目目录不直观时，建议六个目录变量全部填写绝对路径。最重要的是
`APP_DATA_HOST_PATH`，重新编排时不能把它改到新的空目录。

管理员初始账号固定为 `admin/admin`，首次登录后直接在管理后台修改。PanSou 内置服务默认关闭
（`COMPOSE_PROFILES=pansou` 启用），OpenList、网盘、TMDB、通知和分类目录全部在管理后台配置，
不放进 `.env`。

内置 PanSou 说明：

- 内置服务默认不启动。在 `.env` 加一行 `COMPOSE_PROFILES=pansou`（或每次启动命令加
  `--profile pansou`）后重新编排，即随编排启动，应用自动通过容器内网地址 `http://pansou:8888`
  连接，开箱即用。
- 不启用内置服务时，在后台“搜索与线路”填写自建外部 PanSou 地址即可；两种方式不要同时指向
  不同地址造成混淆。
- 后台保存过外部 PanSou 地址的部署，数据库配置优先于编排默认值；想切回内置时，先启用
  `COMPOSE_PROFILES=pansou`，再在“搜索与线路”把地址改回 `http://pansou:8888`
  （不要留空，留空等于关闭搜索）。
- 内置 PanSou 的 TG 频道搜索在国内直连网络下可能超时，插件搜索源不受影响；需要 TG 来源时，
  在 `docker-compose.yml` 的 pansou 服务中取消 `PROXY` 注释并指向可用代理。
- 内置镜像托管在 `ghcr.io`，个别国内网络拉取较慢或失败。此时把 `.env` 中的 `PANSOU_IMAGE`
  改为可用的镜像代理地址（保持 `pansou:标签` 结尾），例如：
  `PANSOU_IMAGE=ghcr.nju.edu.cn/fish2018/pansou:latest`。


### 更新版本

完整维护窗口、冒烟与回滚清单见 [V1 v29 硬切换发布与回滚手册](docs/v1-hard-cutover-deploy.md)。

拉取新镜像不会覆盖宿主机上的 `app.db`。但从旧版单容器/辅助 rclone 容器架构升级时，
**必须同时替换 `docker-compose.yml`，不能只拉取新镜像**。该版本包含数据库 v29 破坏性硬切换，
必须使用维护窗口，禁止新旧容器并存。完整顺序如下：

1. 备份当前 `APP_DATA_HOST_PATH`、`FNOS_ROOT_KEY`、配置目录和 rclone 配置。
2. 停止 Web、Worker、Scheduler 及旧版辅助容器，确认没有进程继续连接 `app.db`。
3. 下载新的 `docker-compose.yml`，确认仍使用原 `APP_DATA_HOST_PATH`，然后拉取新镜像。
4. 在不启动服务的情况下运行硬切换预演，审核保留/删除数量、关联清理数量和 ID 集合哈希：

```bash
docker compose down
docker compose pull
docker compose run --rm --no-deps fnos-media-import \
  python -m fnos_media_import.v1_cutover \
  --database /app/data/app.db --dry-run
```

5. 确认预演结果后执行 `--apply`。命令会获取独占锁、生成迁移前数据库备份、升级到 v29 并执行外键检查：

```bash
docker compose run --rm --no-deps fnos-media-import \
  python -m fnos_media_import.v1_cutover \
  --database /app/data/app.db --apply
```

6. 只有迁移成功后才启动全部新版本进程并执行健康检查：

```bash
docker compose up -d --remove-orphans
docker compose ps
curl -fsS "http://127.0.0.1:${APP_PORT:-5251}/readyz"
```

7. 使用非生产目录验证任务创建、四 Provider 只读探测、移动云/天翼原生 API relay、OpenList、Organizer、取消与恢复后，再解除维护模式。

`--remove-orphans` 只有在新编排已经生效后，才能识别并删除旧版辅助容器。若仍使用旧编排，
新镜像不会再兼容旧角色变量，也不会以 Web-only 模式降级；旧编排缺少显式
`FNOS_PROCESS_ROLE` 时容器会直接启动失败，因此必须先替换编排再更新镜像。

迁移框架仍保留数据库升级能力，但现有部署不得依赖应用启动时自动完成 v29；发布流程必须先离线运行上述
硬切换 CLI。CLI 会在 `APP_DATA_HOST_PATH/backups` 中创建迁移前备份并在 JSON 摘要中返回路径。

`FNOS_ROOT_KEY` 不写入数据库，必须与数据备份分开保存；修改或丢失后，新版敏感数据将无法解密，
现有浏览器登录会话也会全部失效。应用签名密钥由根密钥按 `app-session` 用途稳定派生，不写入
`app.db`；Worker 控制令牌仍保存到 `APP_DATA_HOST_PATH/.secrets`。

硬切换升级前，把现有账号主密钥的值原样改名为 `FNOS_ROOT_KEY`，不要同时保留两个变量名，
也不能临时生成另一条值。程序只接受新版 `v2:<purpose>` 密文；旧 `v1`、`ol:v1` 和旧通知
密文不会自动迁移或回退解密，相关账号、OpenList 连接或通知凭据必须在后台重新登录/保存。
根密钥轮换需要先执行密文迁移，不能直接替换环境变量。

Transfer 的来源可见性、Provider 原生任务、尚未取得回执的搬运等待和取消确认有持久化等待上限。
已取得任务回执的 rclone/中继搬运不按总时长中断：即使剧集较多、传输超过 3 小时，仍按原回执继续查询；
完成后进入目标校验，实际失败、结果未知及取消仍按原有安全流程处理。可通过以下环境变量调整（单位：秒）：

| 变量 | 默认值 | 说明 |
| --- | ---: | --- |
| `TRANSFER_SOURCE_VISIBLE_TIMEOUT_SECONDS` | `1800` | 来源落地区等待 OpenList 可见的最长时间。 |
| `TRANSFER_NATIVE_WAIT_TIMEOUT_SECONDS` | `604800` | 夸克、天翼、六盘等原生任务最长等待时间。 |
| `TRANSFER_WAIT_TIMEOUT_SECONDS` | `10800` | 尚未取得搬运回执的等待上限，以及旧版 v1 中继缓存排队上限；新版有界缓存等待不受此限制，也不是已提交传输的总运行时限。 |
| `TRANSFER_CANCEL_TIMEOUT_SECONDS` | `3600` | 外部取消确认最长等待时间。 |

升级后，后台恢复扫描会自动接续**仅因旧版传输总时长上限**进入人工复核、且冻结计划及原回执一致的任务，
无需重新提交或手动确认；仍使用原入库任务和回执，完成后照常校验。缺失/冲突回执、真正结果未知、
失败、取消和其他人工复核不会自动放行。旧超时原因会保留在执行快照的恢复记录中。

这些超时变量由当前 `docker-compose.yml` 同时传入 Web 和 Worker。修改 `.env` 后需要重新创建容器，
仅执行 `docker compose restart` 不会重新加载环境变量。升级时请同步编排文件，不能只替换镜像。

管理后台等待 Worker 的 `/livez` 健康屏障（共享数据库初始化、HTTP 服务启动完成），不等待业务配置完全就绪。
Worker 的容器健康检查使用该屏障，Web 的容器健康检查仍使用 `/readyz`。因此 OpenList 挂载失效时仍可进入后台修复，
不会出现“Worker 不健康 → Web 无法启动 → 无法修配置”的循环。`/readyz` 仍严格报告未就绪，
实际入库仍受账号、挂载和执行计划校验保护；后台可访问不代表业务链路已经可用。

如果需要从源码构建：

```bash
docker compose -f docker-compose.yml -f compose.dev.yaml up -d --build
```

#### 本轮整理 / 中继修复的更新方式

已使用当前 v29 数据库的部署，本轮不需要再次执行硬切换迁移。先保存完整数据目录和原根密钥，
将修改后的源码同步到 NAS 项目目录，再同时重建两个服务；只重启 Web 或拉取尚未发布的旧 `latest`
不会应用本地源码修复：

```bash
docker compose -f docker-compose.yml -f compose.dev.yaml up -d --build --force-recreate fnos-rclone-worker fnos-media-import
docker exec fnos-rclone-worker sh -c 'command -v flock && grep -m1 "^SCRIPT_VERSION=" /app/scripts/fnos_rclone_worker.sh'
```

脚本版本应显示 `v1.2-live-progress`，构建和 Worker 环境检查都会验证 `flock`。升级后需重新登录管理后台。
修改用户名或密码会撤销其他旧会话，当前修改者保持登录；改回原用户名也不会恢复旧 Cookie 的权限。
回滚本轮代码时保持 Web/Worker 同版本并保留数据和根密钥，不能用旧的全量配置 v1 导入器恢复 v2 备份。

2026-10-11 的剩余问题修复也不新增环境变量或数据库迁移。更新前应先停止接收新任务、等待活动任务结束，
再备份并重建 Web/Worker。已有未完成的 Organizer 回滚必须先在当前版本恢复完成，不能直接降级到不识别
回滚状态的旧代码。发布前仍需用非生产小文件验证实际 OpenList、网盘上传与容器内 `flock`。

普通 rclone 执行结束后的临时写库错误会单独退避补写结果，不重新执行已完成的搬运，也不会把旧结果写到
新任务或新执行批次。补写定时器属于当前进程；补写完成前进程退出或被强杀时，尚未写入的结果不能保证
跨进程保留，启动仍走原有冻结路径恢复。不要靠删除记录或反复新建相同任务绕过这一状态。

**升级后不再要求手动重新保存 OpenList 连接。** Worker 启动及跨盘搬运前会自动检查已保存的连接和实际
rclone Remote。连接身份未变化时，缺少确认标记、旧确认指纹或缺失的 Remote 会通过实际配置同步和连接验证
自动恢复，不修改连接修订、冻结任务计划或已转存的来源文件；已确认的配置不会每次任务重复写入。
若实际 Remote 的类型、地址、用户名或已知 Remote 名称/配置路径发生变化，自动恢复会拒绝覆盖并报告具体原因，
不能靠升级绕过身份校验。连接仍被活动任务使用时，先等待任务安全结束或正常取消，再修改连接身份。

Web 与 Worker 必须共享同一份本地数据库目录。该目录旁会增加 `.openlist-` 命名的锁和确认状态文件：
保留它们，不要在运行中删除文件“解锁”；内核锁会随持有进程结束释放，锁文件留在磁盘上是正常现象。
网络同步超时或结果未知时，不会误报成功，也不会用旧请求覆盖新配置；Worker 在提交前重新核验，仍无法验证时保留任务并报告原因。
以后请以 OpenList 工作区为连接配置入口，raw rclone 配置入口不能另写与数据库不一致的 URL 或账号。
无新增数据库迁移、环境变量或依赖；仍需同时更新 Web 与 Worker，不能只升级一端。

## 4. 注意事项

### 及时修改默认密码

默认账号是 `admin/admin`，只用于第一次登录。修改前不要把管理后台开放到公网。

### 保留持久化目录

默认数据都保存在项目目录中：

```text
config/
data/
logs/
rclone/config/
rclone/temp/
rclone/cache/
```

其中最重要的是：

- `data/`：数据库、任务、后台设置和自动生成密钥。
- `rclone/config/`：rclone 的 OpenList WebDAV 配置。
- `rclone/temp/`：搬运过程中的临时媒体文件。

更新或重建容器不会删除这些目录。迁移机器、重装系统或删除 Compose 项目前必须先备份。

`APP_DATA_HOST_PATH` 中的 SQLite 数据库由 Web 和 Worker 共同访问，必须放在同一台 NAS 的
ext4、Btrfs、XFS、ZFS 等本地文件系统。不要放在 SMB、NFS、CIFS 或其他网络共享中；
SQLite 的 WAL 和文件锁在网络文件系统上无法提供可靠的一致性保证。

### 独立 rclone Worker

标准编排由两个同镜像容器组成：`fnos-media-import` 只提供 Web 和任务生产入口，
`fnos-rclone-worker` 负责调度、后台任务和直接执行 rclone。Worker 不映射宿主机端口，
Web 通过 Compose 内部网络和自动生成的 Bearer Token 调用它。

两个容器都不挂载 `/var/run/docker.sock`，镜像中也不包含 Docker CLI。rclone 仅能访问分配给
Worker 的配置、缓存、临时目录以及应用共享数据目录，不能管理宿主机上的其他容器。

### 日志与健康检查

实时搬运日志不再等文件结束后集中显示：下载统计默认每 5 秒逐行输出，页面每 3 秒独立刷新日志，
不等待较慢的状态或系统日志接口。长时间没有新统计时，下载会持续报告等待/进度未变化；原生上传
默认每 30 秒无新有效进度时报告等待网盘响应，不编造速度或百分比。

后台按任务分别展示下载、上传和秒传校验进度。带文件名的指标是当前文件进度；仅百分比的反馈标为
本阶段指标，都不是整条入库任务的总进度。没有数据时显示未知，不用计时动画模拟下载。
秒传校验不是已上传字节；下载达到 100% 后仍可能等待网盘上传，上传完成后还要经过校验、整理、ACK 和清理。
只有任务已持久化完成后才输出“入库阶段：completed / 入库完成”。

实时指标最多保留 50 个任务，属于当前 Worker 的内存快照，重启后等待新反馈；业务状态仍以数据库为准。
日志持久化保留接收时间，不再将一批进度统一改成落库时间。更新时请等待活动搬运/上传结束后再重建容器，
新脚本启动日志应显示 `v1.2-live-progress`。

- `APP_LOGS_HOST_PATH/web.log`：Web 请求、设置保存和 Worker 调用日志。
- `APP_LOGS_HOST_PATH/worker.log`：调度、后台队列、Organizer 和 rclone 执行日志。
- `/health`、`/livez`：只表示当前 HTTP 进程存活。
- `/readyz`：同时检查数据库、部署安全状态和 Worker 核心运行时；返回 503 时优先查看上述两个日志。

Worker 核心线程持续异常时会主动退出当前应用进程，由 Gunicorn 重建；若整个容器退出，则由
Docker 重启策略恢复。短暂重启期间，Web 查询会自动进行有限重试；启动、停止、取消等有副作用
命令不会自动重试，以免重复执行。

### OpenList 挂载与保存位置必须对应

夸克、移动云等 Provider 的原生目录、OpenList 挂载和最终媒体目录可能位于不同命名空间。
请在“网盘入库”的 OpenList、保存位置和入库规则中完成绑定并执行完整预检；不要再通过
`quark_save_path`、`sixpan_save_path`、`cloud139_target_path` 等旧分类字段手工拼接路径。

不确定时先关闭 Organizer，确认资源能够正常转存后，再单独测试整理功能。

### 合集或识别不准时不要强行整理

遇到电影合集、错误标题或无法确定的文件，建议进入 Organizer 人工审核并选择“跳过整理”。
系统会保留原文件名，只把内容移动到正确分类目录，后续交给 OpenList 或媒体库自行刮削。

正常 TMDB 命中会沿用实际匹配查询的分数，而不是再次用带广告词或编码信息的原始标题把分数压低。
已经确认的高置信 TMDB 命中不会再因文件名解析分数偏低而重复调用 AI、无端转入人工审核。
低置信、目录冲突、缺集等确需处理的情况仍保留人工审核，不会为了自动化直接绕过检查。

选择“广告删除”并保存只修改计划，点击“确认并整理”后才执行实际删除。文件仍会在计划中显示，方便复核。
若文件已移动或删除、只是收尾确认失败，应点击“继续完成确认”，不要先“重新识别”扫描已经搬空的暂存目录；
续跑会保留已完成操作。只有广告、没有保留视频的任务会明确显示清理完成且本次未入库，不会伪装成媒体入库成功。
确认后若计划又被修改，Worker 和本地后台执行都会拒绝旧版本，必须重新确认，防止误用旧批准执行新的广告删除。

若已搬移的文件还需要修改片名或目标，系统会先拒绝改计划，并提示对应的 `run #编号`。
请在该任务的“执行记录”中对指定运行执行“回滚”，恢复暂存位置后再修改并确认；不要直接搬空目录后重新识别。
回滚按持久记录续跑并同步任务状态，重复点击不会重复搬移。发生冲突或部分失败时，应先处理提示并续回滚，
不要同时重新识别或执行新计划。已删除的广告不可恢复；系统不会把这部分删除伪装成可以撤销的操作。
关联追更会撤销本次回滚的完成证据，等待原任务重新确认入库，不会因回滚再创建一份相同下载。

### 历史清理的安全边界

“系统维护 → 直接清理”仍默认不自动备份，保留追更订阅、来源和系统设置。存在排队、运行、自动重试、
未完成取消或回滚时，接口返回 `409 / HISTORY_CLEANUP_BUSY` 并列出阻塞记录，不会删除任何历史。
请等待任务安全结束或通过正常入口完成取消/恢复；此按钮不是停止后台进程的功能。

清理不再重置任务编号，新的编号可能不从 1 开始，这是防止迟到回调和通知投递记录串到新任务的必要保护。
旧版曾重置过编号时，新任务分配还会避开保留的通知审计编号。旧版已经造成的记录丢失或通知漏发不能凭空
恢复，应结合原备份/投递审计确认后处理，不会自动重发可能已经送达的通知。

### 一把根密钥，按用途派生

应用只接受 `FNOS_ROOT_KEY`。程序通过 HKDF-SHA256 派生 Flask 会话、账号、OpenList、授权会话、
来源快照和通知等用途隔离子密钥；不再配置或持久化第二把应用签名密钥。Worker 控制令牌只用于
进程间认证，不是数据加密主密钥。迁移或重装时必须同时保留 `data/` 和原 `FNOS_ROOT_KEY`；
任一丢失都会导致已加密凭据无法解密，替换根密钥还会使现有浏览器会话失效。

### 固定版本更适合长期使用

`latest` 适合首次体验。长期运行时建议把 `APP_VERSION` 固定为明确版本，例如：

```env
APP_VERSION=1.2.0
```

回滚旧镜像时，必须先停止全部新版本进程，再恢复 v29 前的 `data` 备份并启动旧镜像；不能只修改镜像标签，
旧镜像也不能直接读取 v29 数据库。

### 当前兼容范围

- 支持 Linux 容器、Docker Compose v2、`amd64` 和 `arm64`。
- Windows 和 macOS 需要使用 Docker Desktop 的 Linux Container 模式。
- Podman、Kubernetes、Docker Swarm 和 Windows Container 暂不作为支持目标。
- SELinux 严格环境可能需要额外设置挂载目录标签。
